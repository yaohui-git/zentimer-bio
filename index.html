⚠️ 先说最重要的：上一版方案的前提判断错了

我读了 yaohui-git/zentimer 才发现，它不是纯前端 Web App，而是 Android 原生应用（Kotlin 2.2.10 + Jetpack Compose）：完全离线、manifest 里没有 INTERNET 权限、只申请一项通知权限、明确没有练习记录与统计、代码 Apache-2.0（随包音频图片是第三方资产，另授权）。 所以「往 Zen Timer 里嵌一个 Web Bluetooth 插件」在技术上不成立，也会打破它「离线、不多申请权限、不打扰」的产品灵魂。v0.1 的对接方案整体作废。
新架构：你说「这个项目建新库 zentimer-bio」正好是最优解 —— 主 App 管计时与钵声，独立伴侣页管监控/分析/指导，两者手动对齐、互不改动。加蓝牙权限会让主 App 的权限清单从 7 项变 9 项，隐私政策与商店素材全要重写，不值得。

两个必须讲清楚的技术结论

议题结论怎么做
小米手环 3/4不能作为 HRV 数据源。规格不支持 HRV、只给瞬时心率；BLE 是华米私有协议（AES 认证 / 运动心率广播），不提供标准 RR 间期流，而 RMSSD / 0.1 Hz 相干性必须基于逐拍 RR。只作瞬时心率的粗略对照。既然可报销，建议补一条标准 BLE 心率带（CooSpo H808S ¥140–260 / Polar H9 ≈ ¥498 推荐 / Polar H10 ¥600–750），阶段 0 就能拿真实 HRV，且作为全程校准金标准。把钱花在尺子上，而不是提前买 EEG。
iOS 与通道你说先不管 iOS，所以不做原生 App / Apple 账号。但把主通道定为 ESP32 开 AP 热点 + 自托管页面 + WebSocket 后，普通 HTTP/WS 所有浏览器都支持，顺带把 iOS / Firefox 也覆盖了，零额外成本。主通道：http://192.168.4.1，完全离线自持、无需 HTTPS、无需外网。辅通道：Web Bluetooth（桌面调试 + 接第三方心率带）。
